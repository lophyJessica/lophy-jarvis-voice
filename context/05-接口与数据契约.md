# 05-接口与数据契约

> 原则（用户 2026-08-03 拍板）：**后端定义契约（权威、稳定），前端做适配调用**。接口调用方可能不止一个（网页/未来 APK/其他客户端），后端绝不迁就前端历史接口。
> 本文件描述当前前后端契约，供维护对齐。

## 1. 接口总览

| 接口 | 方法 | 用途 | 认证 |
|---|---|---|---|
| /p/jarvis/auth/login | POST | 登录 | - |
| /p/jarvis/auth/verify | GET+POST | token 校验 | Bearer |
| /p/jarvis/v1/chat/completions | POST | 对话（SSE） | Bearer |
| /p/jarvis/history | GET/POST/DELETE | 记忆同步 | Bearer |
| /p/jarvis/asr-stream/start | POST | 流式会话创建 | - |
| /p/jarvis/asr-stream/chunk | POST | 音频块上传 | X-Session-Id |
| /p/jarvis/asr-stream/end | POST | 会话结束拿最终文本 | - |
| /p/jarvis/asr-stream/health | GET | 健康检查 | - |
| /p/jarvis/file/upload | POST | 文档保存 | X-Jarvis-User |
| /tts | GET | Edge TTS 播报 | - |

## 2. 认证契约

### 2.1 登录 login

```
POST /p/jarvis/auth/login
Body: { "username": "lophy", "password": "123456" }
响应: { "ok": true, "token": "<jwt>", "username": "lophy" }
```

- 密码校验：VPS 后端 SHA256(salt+password)（users.json 键名 `hash`，非 password_hash）
- 登录响应**必须含 ok:true**（前端 `!w.ok` 判失败）
- token TTL 7 天

### 2.2 校验 verify

```
GET/POST /p/jarvis/auth/verify
Header: Authorization: Bearer <token>
响应: { "ok": true, "username": "lophy" }
```

- **GET+POST 双路由**（nginx auth_request 用 GET 子请求，只 POST 会 405 拦 chat/completions）
- 改密后：清该用户所有 token，旧 token verify → 401

### 2.3 401 处理

- 前端所有 API 401 统一：清 token → 跳登录页「登录已过期」
- 不再显示「罗宾暂时不可用」

## 3. 对话契约

```
POST /p/jarvis/v1/chat/completions
Header: Authorization: Bearer <token>
Body: OpenAI 兼容（messages 数组，content 支持 string 或 content[] 多段）
响应: SSE 流式（OpenAI 格式）
```

content 多段格式（图片/文档）：

```json
[
  { "type": "text", "text": "用户文字或【用户指令】xxx" },
  { "type": "text", "text": "【文档内容】文件名：\n请读取文件 /path 并处理以上指令。" },
  { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }
]
```

## 4. 记忆契约

```
GET  /p/jarvis/history?limit=50   → { "messages": [...] }
POST /p/jarvis/history             → Body: { "messages": [...] }（每用户保留 500 条）
DELETE /p/jarvis/history           → 清空
```

- SQLite（/var/lib/jarvis/jarvis.db，users + messages 表，WAL）
- GET 默认 50 条 + 剥离图片 base64（防卡页面）
- 旧 JSON 备份 json-backup-*（不删）

## 5. 流式 ASR 契约（v100+，前端 asrStream.ts 严格一致）

### 5.1 start

```
POST /p/jarvis/asr-stream/start
Body: {}（可空）
响应: { "ok": true, "session_id": "<非空字符串>" }
```

- 每次 start 新建百度会话；不复用已失效空闲 session

### 5.2 chunk

```
POST /p/jarvis/asr-stream/chunk
Header: X-Session-Id: <session_id>
Header: Content-Type: audio/pcm
Body: 16kHz / mono / s16le 裸 PCM 流（320ms ≈ 10240B/批）
响应: { "ok": true, "text": "<MID 累积句，单调增长>" }
```

- **有语音时不能长期 text 为空**（流式命中判定）
- text 是「定稿句 + 当前句 MID」的单调增长字符串，前端按前缀扩展展示
- 任何异常降级 {ok:true, text:已有文本}，**永不 5xx**
- 录音中只发 PCM；webm 仅收尾兜底（/asr）

### 5.3 end

```
POST /p/jarvis/asr-stream/end
Body: { "session_id": "<同上>" }（前端只发 body，不靠 Header）
响应: { "ok": true, "text": "<FIN 最终整句>" }
```

- 收尾以此为准发送

### 5.4 降级 /asr（webm 兜底）

```
POST /asr
Header: Content-Type: audio/webm
Body: webm 音频
响应: { "text": "<整段识别>" }
```

- 用途：chunk 连续失败 / 流式完全无 MID / 收尾补全
- 本地 dev 需代理到 VPS；生产 nginx 要有 /asr

## 6. 文档上传契约

```
POST /p/jarvis/file/upload
Header: X-Jarvis-User: <username>
Body: multipart/form-data，字段名 file
响应: { "ok": true, "filename": "...", "path": "/var/lib/jarvis/files/<user>/...", "size": N, "ext": "pdf" }
```

- 白名单 40+ 类型：pdf/docx/xlsx/txt/md/html/yaml/json/js/ts/tsx/css/py/go/rust/c/cpp/sql/toml/zip/tar/gz/rar/7z/png/jpg/gif/webp/svg 等
- 保存路径 /var/lib/jarvis/files/{username}/
- 文档内容不渲染：前端只显示 📄 文件名 + 指令

## 7. TTS 契约

```
GET /tts?text={encodeURIComponent(文本)}
响应: MP3 音频流
```

- Edge TTS，台湾腔 zh-TW-HsiaoChenNeural
- 前端句子切分 → 逐句请求 → 预取 3 段流水线播放

## 8. nginx 层要求

- /p/jarvis/asr-stream/* 透传 POST body（勿缓冲丢 chunk）
- client_max_body_size 足够（chunk 10KB 级，上传文件 50m 级）
- 超时 ≥30s（前端单请求超时）
- chunk 不 strip X-Session-Id
- end 接受 JSON body 里的 session_id
- /p/ 只转 Hermes API 8642；/p/jarvis/history 需专门 location 转 8868；asr-stream 转 8869；file/upload 转 8871（proxy_pass 带 /file 后缀）
