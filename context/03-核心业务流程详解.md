# 03-核心业务流程详解

## 1. 登录流程

### 1.1 流程描述

```
用户打开 /jarvis-voice/
  → 检查 localStorage 是否有 jarvis-token
  → 有 token：尝试进入主界面（若 401 则清 token 回登录页）
  → 无 token：显示登录页
  → 输入 username + password
  → POST /p/jarvis/auth/login
  → 校验成功：返回 { token, username }，存 localStorage
  → 进入主界面，GET /p/jarvis/history 拉取记忆
```

### 1.2 关键点

- 密码 VPS 后端 SHA256(salt+password) 校验
- token TTL 7 天
- 401 处理：清 token → 回登录页提示"登录已过期"
- isDev（localhost/127.0.0.1）：跳过登录直接进主界面

## 2. 语音实时对话流程（核心）

### 2.1 状态机

```
idle(listening) → recording → transcribing(实时出字) → thinking → speaking → idle
        ↑________________________________打断__________________|
```

### 2.2 详细步骤

**阶段一：监听（idle）**
1. 页面加载 → getUserMedia({audio:true}) → AudioContext
2. AnalyserNode 实时分析音量（getByteTimeDomainData）
3. 音量超阈值（0.02-0.05）持续 300ms → 判定"开始说话"

**阶段二：录音 + 流式识别（recording → transcribing）**
1. 触发 AudioWorklet 采集（128 帧/批，16k 重采样，Float32→Int16）
2. 调 POST /asr-stream/start 创建会话（拿 session_id）
3. 每 320ms 累积一批 PCM → POST /asr-stream/chunk
   - header: X-Session-Id + Content-Type: audio/pcm
   - VPS 端 PCM 直通百度（无需转码）
4. 响应 text 数组 → **取最后一条替换**"识别中"显示区
   - 注意：MID_TEXT 是完整累积文本，不是增量，不能追加
5. 循环直到静音

**阶段三：结束识别（→ thinking）**
1. 音量低于阈值持续 1.5s → 判定"说完"
2. POST /asr-stream/end → 拿 FIN_TEXT 最终文本
3. 清空"识别中"区 → 最终文本作为用户消息进列表

**阶段四：对话（thinking）**
1. 用户消息 + 历史 → POST /p/jarvis/v1/chat/completions（Bearer token）
2. SSE 流式接收回复 → 实时渲染（markdown）
3. 显示"停止思考"按钮（AbortController 可中断）

**阶段五：播报（speaking）**
1. 回复文本 → GET /tts?text=URL编码 → MP3
2. Audio 播放（台湾腔）
3. VAD 持续监听：检测到用户说话 → audio.stop()（打断）→ 回 recording

**阶段六：记忆同步**
1. 每轮完整对话结束 → POST /p/jarvis/history（messages.slice(-200)）
2. 失败静默（console.error），不影响使用

### 2.3 降级路径

```
AudioWorklet 初始化失败
  → 回退 MediaRecorder（audio/webm）
  → 停止后整段 POST /asr（百度短语音）
  → 识别结果一次性显示（无实时出字，但可用）
```

### 2.4 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| VAD 阈值 | 0.02-0.05 | 音量触发 |
| 说话判定 | 300ms 连续超阈 | 开始录音 |
| 静音判定 | 1500ms 连续低阈 | 结束录音 |
| PCM 批次 | 320ms | 上传间隔 |
| PCM 格式 | Int16 LE 16kHz | 百度要求 |
| 百度帧 | 160ms = 5120B | 每帧 |
| 请求超时 | 120s（12e4） | 对话/ASR/TTS |

## 3. 跨浏览器记忆流程

### 3.1 初始化

```
登录成功 → GET /p/jarvis/history?limit=200
  → 云端记录作为消息列表初始数据
  → 加载中显示"同步中…"
  → GET 失败 → IndexedDB 缓存兜底
```

### 3.2 写入

```
每轮对话结束（用户消息+罗宾回复都生成后）
  → POST /p/jarvis/history（body: {messages: 完整列表.slice(-200)}）
  → 失败静默
```

### 3.3 注意

- 初始化 GET 完成前**禁止 POST**（避免覆盖云端）
- 不用 messages 变化的 useEffect 自动 POST（防竞态）
- 显式在对话轮次结束后 POST 一次

## 4. 图片识别流程（融合后）

### 4.1 流程

```
粘贴图片（Ctrl+V）
  → canvas 压缩（max-width 800px, JPEG quality 0.6）
  → 缩略图显示在输入框
  → 发送时 content 构造：
    [
      {type:"text", text:"用户文字"},
      {type:"image_url", image_url:{url:"data:image/jpeg;base64,..."}}
    ]
  → POST /p/jarvis/v1/chat/completions
  → Hermes 检测到 image_url → vision_analyze 工具
  → Gemini-3.1-Flash-Lite 识别图片（~3.7s）→ 文字描述
  → 主模型（DeepSeek）基于描述回答
```

### 4.2 关键点

- 图片必须 content[] 数组格式（非 Markdown ![图片]）
- vision 辅助模型配置在 auxiliary.vision（主配置 + profile 两处）
- custom_providers 必须是 YAML list（带 '-' 前缀）
- 前端超时 120s（识别 10-15s + 传输）

## 5. TTS 播报流程

```
回复文本 → GET /tts?text={encodeURIComponent(文本)}
  → VPS 8866 Edge TTS（zh-TW-HsiaoChenNeural）
  → 返回 MP3 → Audio 播放
  → 播放中 VAD 检测到说话 → audio.pause() 打断
```

## 6. 异常处理

| 场景 | 处理 |
|---|---|
| start 500 | 前端报"流式识别启动失败"，降级整段 /asr |
| chunk 500 | 静默重试一次，仍失败降级 |
| 对话 401 | 清 token 回登录页"登录已过期" |
| TTS 失败 | 静默，文字回复仍显示 |
| 记忆 POST 失败 | console.error，不影响界面 |
| AudioWorklet 失败 | MediaRecorder 降级 |
