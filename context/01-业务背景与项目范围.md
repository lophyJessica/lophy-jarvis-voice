# 01-业务背景与项目范围

> 文档状态：2026-08-04 按「当前最终版」重写。语音版已收尾定稿，本文档描述**真实现状**；文字版融合规划归入 §6 历史路线。

## 1. 业务背景

### 1.1 起源

用户（路飞/Lophy）从 2026-07 起构建个人 AI Agent「罗宾」（Robin），经历三个阶段：

1. **文字版（lophy-jarvis）**：独立仓库，Web 控制台，登录 + 聊天 + 跨浏览器记忆 + 图片识别
2. **语音版（lophy-jarvis-voice，本仓库）**：语音实时对话优先，VAD 免按钮 + 百度流式 ASR + Edge TTS 播报；随后补入文字输入、图片识别、文档识别，形成**双模式单入口**的完整形态
3. **融合版（历史规划）**：文字版与语音版合并为单一入口。**当前状态：文字版与语音版各自独立运行，融合为远期路线，无排期**

### 1.2 为什么做罗宾

- 个人 AI 助理，区别于飞书（工作协作）/微信（社交）
- 核心价值：**对话即操作**——问、看、听、办
- 三端定位：路飞（用户本人）、罗宾（网页端 AI）、杰西卡（飞书端助手）
- 产品理念：一个大脑（Hermes + 模型），多个入口（网页/飞书），共享记忆

## 4. 关键约束（AI 改代码必须遵守）

1. **物理隔离**：本项目禁止碰 lophy-jarvis（文字版）代码
2. **降级保护**：MediaRecorder 整段识别路径**必须保留**（AudioWorklet 失败兜底）
3. **版本快照**：每轮修改入 versions/v{n}/，旧版本不删除
4. **浏览器自查**：AI 改完必须自己 `npm run build` + 浏览器验证
5. **成本敏感**：主模型走 DeepSeek 官方直连（稳定省钱），中转仅 vision 用
6. **不 commit/push/部署**：除非用户明确要求
7. **后端契约**：VPS 后端是权威，前端适配调用；后端不迁就前端历史接口

## 5. 语音功能定位（重要）

**语音输入已不再迭代**：2026-08-04 用户明确——微信语音输入更准更方便，语音版降级为不重要的辅助功能。当前百度流式 ASR 链路保持可用即可（收尾定稿，Opus 重构版后端稳定），**不投入新开发**。TTS 播报（罗宾回复朗读）保留。
